# PostgreSQL 역사 완전판 — 스토리보드

## 중심 질문

> 관계형 모델을 버리지 않으면서, PostgreSQL은 어떻게 새로운 데이터 세계를 받아들였는가?

- NanumMyeongjo 제목 + Pretendard 본문
- 아이보리·잉크·산화 오렌지·연구실 녹색
- 반복 카드 대신 슬라이드별 전용 도식

## 슬라이드

1. **표지 — 관계형 DB가 이해하는 세계를 넓히다**
   시각: 어두운 배경의 거대한 database strata와 궤도형 타입 심볼.

2. **전체 논지 — 네 번의 전환**
   시각: 세로로 접힌 4막 아코디언 타임라인. INGRES → POSTGRES → Postgres95 → PostgreSQL.[2][3][5]

3. **이론·연구·제품·코드는 서로 다른 계보다**
   시각: Codd에서 네 갈래로 분기하는 가계도.[1][2][5][22]

4. **INGRES — WHAT과 HOW의 분리**
   시각: 왼쪽의 사용자 질문이 오른쪽 DBMS 내부의 네 개 결정을 관통하는 편집물형 단면.[2]

5. **새로운 데이터는 테이블 밖에서 왔다**
   시각: CAD 도면·지도 polygon·과학 파형을 한 장의 기술 도면처럼 조합.[3][4]

6. **패치가 아니라 재설계**
   시각: INGRES 위에 쌓인 기능 블록이 기울어지고, POSTGRES가 별도 기반으로 갈라지는 구조.[3][4]

7. **Object–Relational — 버린 것과 유지한 것**
   시각: 찢어진 두 문장과 하나의 합성 문장. 관계형 모델 폐기에는 X, 표현력 확장에는 강조.[3][4]

8. **새 타입의 해부도**
   시각: 중앙 타입 값에서 내부 표현·I/O·함수·연산자·operator class가 폭발도처럼 분해.[6][7][8][9]

9. **polygon이 쿼리 계획에 들어오는 과정**
   시각: 좌표 문자열부터 optimizer까지 이어지는 한 줄 conveyor.[3][4][9]

10. **POSTGRES 설계 선언문 여섯 줄**
    시각: 연구 선언문 포스터. 여섯 목표를 서로 다른 타이포 크기로 구성.[3]

11. **연구 계보와 코드 계보**
    시각: 위쪽 점선은 연구 영향, 아래쪽 실선은 직접 코드 연속성을 나타내는 두 레일.[2][3][5]

12. **오픈소스라는 이름보다 문화가 먼저였다**
    시각: 1950s 공유 → BSD → GNU/GPL → Linux → Postgres95 → 1998 Open Source의 시대 리본.[13][14][15]

13. **프로젝트를 끝낸 것은 실패가 아니라 지원 비용이었다**
    시각: 연구와 지원 시간을 대비한 기울어진 저울과 1989·1993·1994 사건.[5][12]

14. **Postgres95 — SQL을 위한 실용적 계속 작업**
    시각: PostQUEL 페이지 위에 SQL 교정지가 붙은 연구 노트.[5][11][23]

15. **커뮤니티가 코드의 다음 주인이 되다**
    시각: 한 명의 연구팀에서 전 세계 노드로 퍼지는 메일링리스트 네트워크.[5][11][17]

16. **확장 철학의 현대적 패키징**
    시각: 코어 원형을 둘러싼 TYPE·FUNCTION·OPERATOR·OPCLASS 궤도와 EXTENSION PACKAGE 링.[6][7][10]

17. **MySQL과 POSTGRES는 출발 질문부터 달랐다**
    시각: 서로 다른 질문에서 출발해 현재 RDBMS로 향하는 두 개의 대각선.[3][16][18]

18. **상세 산업 연표 — IBM·Berkeley·Oracle**
    시각: 1970~1983 신문 지면형 3열 타임라인. Codd, System R·INGRES, Oracle 전신 설립·Oracle V2, DB2.[1][22]

19. **POSTGRES 버전·공개 연표**
    시각: 철도 노선표. 1987 demo, 1988 SIGMOD, 1989 V1 외부 배포, 1990 V2, 1991 V3, 1994 V4.2 FTP, 1995 web.[5][12]

20. **Postgres95 수술 기록 — 바뀐 것과 아직 없던 것**
    시각: 좌우 diff. SQL·ANSI C·25% 축소·psql·성능 개선 / 서브쿼리 등 당시 SQL 제약.[11][23]

21. **MySQL 제품화·MyISAM·MariaDB 상세 계보**
    시각: 제품·코드 계보(MySQL→MariaDB fork), 엔진 직접 계보(ISAM→MyISAM), 외부 엔진 통합(Innobase Oy→InnoDB)을 분리한 3구획 도식.[16][19][24]

22. **MyISAM과 InnoDB는 같은 엔진의 전후 버전이 아니다**
    시각: MySQL Server 섀시 안에 서로 다른 두 엔진을 끼운 분해도.[18][19][24]

23. **소유권은 코드 계보가 아니다**
    시각: 2005·2008·2010 인수 흐름과 최종 소유자를 보여 주되 PRODUCT·SERVER·ENGINE 기술 층위를 별도로 구분.[19][20][21]

24. **헷갈리기 쉬운 여섯 문장 교정**
    시각: 빨간 교정 기호가 들어간 proof sheet. 잘못된 표현 → 정확한 표현.[3][5][13]

25. **어떤 설명을 선택할 것인가**
    시각: 4개 설명 프레임을 비교하고, ‘확장 가능한 관계형 DB + SQL + 커뮤니티 계승’을 추천 결론으로 강조.[3][5][6]
