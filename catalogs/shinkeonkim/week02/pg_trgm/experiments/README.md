# pg_trgm 실험 - 정량 벤치마크

[`../labs/`](../labs) 가 "이 확장이 어떻게 동작하는지" 보여주는 실습이라면, 여기는 **실제로 측정한 숫자**로 답한다. 각 실험은 독립된 Docker 컨테이너(`./bench.sh`)로 재현 가능하고, README 에는 실제로 그 스크립트를 실행해서 나온 값만 적혀 있다.

| 실험 | 질문 | 핵심 발견 |
| --- | --- | --- |
| [01-gin-vs-gist-build-and-probe](01-gin-vs-gist-build-and-probe) | GiST 의 `siglen` 은 실제로 얼마나 중요한가 | **`siglen` 을 키우면 인덱스가 오히려 작아진다** (긴 문서 249 → 144 MB). 버퍼는 12 → 256 에서 31,7xx → 2,7xx 로 떨어지는데, **128 까지는 완만하고 256 에서 급락한다** — "조금 올려보고 효과 없으면 포기"하면 안 된다. 그래도 GIN 의 212~218배다. **2회 실행에서 GIN 은 완전히 동일했고 GiST 는 ±5% 흔들렸다** |
| [02-threshold-and-knn-latency](02-threshold-and-knn-latency) | 임계값과 KNN 의 실제 비용 | **임계값을 0.3 → 0.05 로 낮추면 인덱스가 돌려주는 후보가 9행 → 12,130행** 으로 늘어나는데 **인덱스 버퍼는 38 그대로다** (비용은 힙 재확인에서 난다). `similarity()` 는 검색어가 그대로 들어있는 45글자 문서를 **길다는 이유만으로 놓친다**(0.25 < 0.3). **4회 실행에서 임계값 스윕·재현율은 완전히 동일**했고, KNN `LIMIT 1` 만 재현되지 않았다 |

`pg_bigm` 과의 비교 실험은 [`../../bigm-vs-trgm/experiments/`](../../bigm-vs-trgm/experiments) 에 따로 있다.

## 데이터

두 실험 모두 [NSMC](https://github.com/e9t/nsmc)(Naver Sentiment Movie Corpus, **CC0**) 한국어 말뭉치 199,993문장을 쓴다. `bench.sh` 가 실행 시점에 `.corpus/` 로 내려받아 캐시하고(커밋하지 않는다), 네트워크가 없으면 합성 데이터로 폴백한다. 검색 대상 예시 문자열은 스터디 공용(`클라우드클럽` 등)으로 통일했다 — 배경은 [`web/#/meta/method`](../../../web/README.md).

## 측정 과정에서 고친 버그

이 실험들을 만들며 실제로 걸렸던 것들이다. 재현하려는 사람이 같은 함정에 빠지지 않도록 남긴다.

- **`EXPLAIN ANALYZE` 의 노드 줄 형식은 `TIMING` 설정에 따라 다르다.** `TIMING ON` 이면 `(actual time=1.2..3.4 rows=200 loops=1)`, `TIMING OFF` 면 `(actual rows=200 loops=1)`. `actual rows=` 로만 파싱하면 시간을 함께 재는 스크립트에서 조용히 빈 값이 된다.
- **`psql -tAc "SET ...; SELECT ..."` 는 `SET` 의 명령 태그까지 출력한다.** 숫자만 필요하면 `| tail -1` 이 필요하다.
- **`VACUUM` 은 트랜잭션 블록 안에서 못 돈다.** `psql -c "A; B; VACUUM"` 처럼 한 `-c` 에 세미콜론으로 이으면 하나의 트랜잭션이 되어 실패한다 — `-c` 를 나눠야 한다.
- **정답 행을 `LIKE` 로 골라내면 말뭉치가 섞여 들어온다.** `'%클라%'` 로 심어둔 6건을 고르려 했더니 `클라스`·`클라라`·`클라이맥스` 가 수십 건 걸렸다. `id` 로 특정해야 한다.
