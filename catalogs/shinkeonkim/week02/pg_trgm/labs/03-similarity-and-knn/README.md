`pg_bigm` 의 유사도는 `=%` 하나뿐이다. `pg_trgm` 은 세 가지 유사도와 KNN 정렬을 갖고 있는데, **셋의 의미가 실제로 다르다.**

조사 문서는 [`../../docs/`](../../docs)에, 종합 카탈로그 문서는 [`../../README.md`](../../README.md)에 있다.

## 직접 확인한 것

- **`similarity()` 는 본문이 길수록 무너진다.** 같은 `'제브라'` 를 찾는데 본문 길이에 따라 0.5714 → 0.1111 → 0.0563 으로 떨어졌다. 반면 `word_similarity()` 는 세 경우 모두 1.0 이었다. **긴 본문에서 짧은 검색어를 찾을 때 `similarity()` 를 쓰면 안 된다**는 뜻이다 - 임계값을 아무리 낮춰도 본문 길이가 점수를 결정해버린다.
- **임계값 GUC 가 연산자마다 다르다**: `%` 는 0.3, `<%` 는 0.6, `<<%` 는 0.5. 하나만 바꾸고 다 바뀌었다고 생각하기 쉽다.
- **KNN 은 임계값과 무관하다.** `% ` 연산자라면 0건이었을 검색어에도 `ORDER BY <-> LIMIT 3` 은 "그나마 가까운 3건"을 돌려준다 - "검색 결과 없음"을 피해야 하는 UI 에서 유용하고, `pg_bigm` 에는 대응물이 없다.
- `set_limit()`/`show_limit()` 은 9.6 이후 폐기됐지만 아직 동작한다 - 오래된 블로그를 따라 하다 혼동하기 쉬운 지점이다.
