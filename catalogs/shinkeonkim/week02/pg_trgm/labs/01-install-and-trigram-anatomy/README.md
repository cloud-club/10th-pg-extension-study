# Lab 01 - 설치와 트라이그램 해부

```bash
./run.sh          # 약 30초
```

> **두 가지 방법으로 볼 수 있습니다.**
>
> | | 명령 | 언제 |
> |---|---|---|
> | **자동** | `./run.sh` | 전체 흐름을 빠르게 훑어볼 때 |
> | **직접** | [`HANDS-ON.md`](HANDS-ON.md) | psql 에 접속해 **한 줄씩 쳐보며** 확인할 때 |
> 처음이라면 `./run.sh` 로 한 번 흘려보고, `HANDS-ON.md` 로 다시 짚어보는 순서를 권합니다.

`show_trgm()` 출력만 보고 **"이 검색어는 인덱스를 제대로 탈 수 있는가"** 를 판단할 수 있게 되는 것이 목표다. 설치 난이도, trusted 확장, 패딩, 멀티바이트 해싱, 유사도 공식을 한 번에 훑는다.

조사 문서는 [`../../docs/`](../../docs)에, 종합 카탈로그 문서는 [`../../README.md`](../../README.md)에 있다.

## 직접 확인한 것

- **`pg_trgm` 은 한글을 걸러내지 않는다.** `show_trgm('가나다라')` 가 조각 5개를 정상 생성한다 - "KEEPONLYALNUM 때문에 한글이 안 된다"는 흔한 설명은 틀렸다. `ISWORDCHR` 가 쓰는 `t_isalnum_with_len()` 은 멀티바이트를 인식한다. `0x...` 로 보이는 건 별개 이유(3바이트 고정 타입 + CRC32 해싱)다.
- **구두점 처리도 다르다.** `192.168.0.1` 이 `192`/`168`/`0`/`1` 로 쪼개진다 - IP·버전·경로·식별자 검색에서 실제로 걸린다.
- **`trusted = true` 한 줄로 설치 권한이 갈린다.** 수퍼유저가 아닌 롤로 `CREATE EXTENSION pg_trgm` 이 성공하는 것을 직접 재현한다 (`pg_bigm` 은 같은 자리에서 실패한다).
- **이 lab 의 `Dockerfile` 은 22줄이다.** `pg_bigm` lab 의 54줄짜리 소스 빌드 Dockerfile 과 비교해 보라 - 그 차이 자체가 실무 선택 기준 중 하나다.
