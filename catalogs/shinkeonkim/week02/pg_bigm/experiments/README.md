# pg_bigm 실험 - 정량 벤치마크

`../labs/`가 "이 익스텐션이 어떻게 동작하는지" 보여주는 실습이라면, 여기는 **실제로 측정한 숫자**로 답하는 곳이다. 각 실험은 독립된 Docker 컨테이너(`bench.sh`)로 재현 가능하고, README.md에는 실제로 그 스크립트를 실행해서 나온 값만 적혀 있다.

| 실험 | 질문 | 핵심 발견 |
| --- | --- | --- |
| [00-explain-before-after](00-explain-before-after) | `docs/01` 의 Before/After 는 **몇 행부터** 실제로 그렇게 되나 | **100행에서는 인덱스가 있어도 `Seq Scan`** 이다. 그리고 1,000행에서는 같은 테이블·같은 인덱스인데 **검색어에 따라 플랜이 갈린다**(선택도 0.1% → 인덱스, 30% → Seq Scan) — 전환점은 행 수 하나로 정해지지 않는다 |
| [01-index-build-time-and-size-vs-pg_trgm](01-index-build-time-and-size-vs-pg_trgm) | 인덱스 빌드 시간·크기가 bigm 과 trgm 사이에 얼마나 차이 나나 | **빌드 시간은 동률**이고 **크기는 trgm 이 27~73% 크다**. 격차가 규모에 따라 줄어든다(5만 1.73× → 100만 1.27×) — 엔트리 트리가 고정비이기 때문. 문서의 "~102MB vs ~228MB" 는 컬럼 최대 크기 제한이지 인덱스 크기 배수가 아니었다 |
| [02-query-latency-at-scale](02-query-latency-at-scale) | 짧은/긴 키워드 검색이 규모가 커질수록 얼마나 벌어지나 | **2글자 키워드에서 trgm 인덱스는 인덱스가 없는 것보다 10~16배 느리다** — 인덱스 스캔이 **테이블 전체**를 후보로 올리고(50,000 / 200,000 / 1,000,000) Recheck 이 99.9% 를 걸러낸다. 6글자에서는 둘이 동률 |

각 실험 디렉터리에서 `./bench.sh`를 실행하면 직접 재현할 수 있다 (`./bench.sh down`으로 정리).

## 데이터에 대한 주의

**세 실험 모두 이제 실제 한국어 말뭉치([NSMC](https://github.com/e9t/nsmc), CC0)를 쓴다.**

01·02 는 원래 어휘 15문장짜리 합성 데이터 + `random()` 을 썼는데, 그것이 두 가지 문제를 만들었다.

1. **02 가 3회차에서 재현되지 않아 핵심 주장을 철회**했다 — `random()` 에 시드가 없어 데이터 자체가 실행마다 달랐고, "짧은 키워드"로 쓴 `검색` 이 전체 행의 **55.6%** 와 매치돼 선택도가 통제되지 않았다.
2. **01 의 크기 차이가 "5~13%" 로 나왔는데, 실제 말뭉치에서는 27~73%** 였다 — 반복도가 높으면 두 인덱스 모두 유니크 조각이 적어져 격차가 사라진다.

**둘 다 말뭉치 + `generate_series` 나머지 주입으로 다시 만들었고, 각 README 에 1차/2차 대조를 남겨 두었다.** 이 경험에서 이 카탈로그의 [측정 원칙](../../bigm-vs-trgm/experiments/README.md#측정-원칙)이 나왔다.

`pg_trgm` 과의 비교는 [`../../bigm-vs-trgm/experiments/`](../../bigm-vs-trgm/experiments) 에 따로 있다.
