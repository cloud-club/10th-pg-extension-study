# 기본 01 · 방문 횟수와 실제 사람 수

## 고유 개수부터 정의하기
민수·민수·지수·현우·민수라는 기록이 있습니다. 기록은 5개지만 이름의 종류는 3개입니다. 이 종류 수가 고유 개수, 즉 cardinality입니다. 먼저 무엇을 같은 대상으로 취급하는지 정해야 합니다. 실제 서비스에서는 이름보다 안정적인 사용자 ID를 사용합니다.

```sql
WITH visits(user_id) AS (VALUES (1),(1),(2),(3),(NULL))
SELECT count(*) AS events,count(user_id) AS known_events,
       count(DISTINCT user_id) AS known_users
FROM visits;
```
결과는 5·4·3입니다. COUNT(*)는 행, COUNT(user_id)는 NULL이 아닌 값, COUNT(DISTINCT user_id)는 NULL이 아닌 서로 다른 값의 수를 셉니다. NULL을 익명 사용자 한 명으로 계산할지는 업무 정책입니다. NULL에 임의 ID를 붙이기 전에 여러 익명 방문을 모두 같은 사람으로 취급해도 되는지 묻습니다.

## 집합을 손으로 만들기
| 읽은 값 | 지금까지 본 집합 | 고유 개수 |
| --- | --- | --- |
| 1 | {1} | 1 |
| 1 | {1} | 1 |
| 2 | {1,2} | 2 |
| 3 | {1,2,3} | 3 |

정확한 방법은 어떤 값이 이미 있었는지 기억합니다. 이벤트를 다시 받았다고 고유 사람이 늘지 않습니다. 이벤트 중복 제거와 사람 고유 개수는 서로 다른 질문입니다.

## 어떤 ID를 셀 것인가?
계정·기기·세션·쿠키는 다른 대상입니다. 학생이 휴대폰과 노트북으로 방문하면 기기 수 2, 계정 수 1일 수 있습니다. HLL은 이 정의를 대신 결정하지 않습니다. 데이터가 섞이면 정확한 COUNT DISTINCT도 의도한 사람 수가 아닐 수 있습니다.
