# Lab 03 · 정밀도·공간·오차 분포

## 같은 값의 반복과 다른 표본을 구분
오차 분포에는 서로 다른 입력 집합이 필요합니다. 이 Lab은 trial-0/user-1부터 trial-19/user-50000까지 20개의 문자열 네임스페이스를 사용하며 각각 정답 50,000입니다. 해시 seed는 0으로 고정합니다. 시행 번호와 해시 seed를 구분해 기록합니다.

```sql
SELECT hll_cardinality(hll_add_agg(
 hll_hash_text('trial-0/user-'||i,0),11,5,0,0)),
 octet_length(hll_send(hll_add_agg(
 hll_hash_text('trial-0/user-'||i,0),11,5,0,0)))
FROM generate_series(1,50000) i;
```
log2m 8·11·14를 비교하고 regwidth=5, expthresh=0, sparseon=0으로 고정합니다. 작은 목록·희소 표현의 영향을 제외하고 FULL payload와 오차를 비교하기 위한 통제입니다.

## 기록할 값
시행별 추정·binary bytes, signed error 평균, RMSE, 최대 절대 상대 오차와 이론 RSE 모델을 기록합니다. 20회 표본은 큰 데이터 범위 전체의 보장이나 엄밀한 확률 검증이 아닙니다. 한 시행에서 고정밀 설정이 더 나쁘다는 이유만으로 이론 모델을 틀렸다고 선언하지 않습니다.

## 그림 1 · 평균으로 숨기지 않은 20개 오차
![실측 · log2m별 상대 오차 20시행. 점은 원시 시행, 상자는 가운데 50% 범위, 상자 안 선은 중앙값입니다.](/hll/plots/lab03-error-distribution.svg)
0 위의 점은 과대 추정, 아래는 과소 추정입니다. 이번 표본에서는 log2m=8의 점이 넓게 흩어지고 11·14는 더 좁아졌습니다. 같은 ID 집합을 같은 seed로 반복 실행한 표본이 아니라 다른 네임스페이스의 ID 집합을 사용했습니다. 한 점의 오류만 보거나 평균 부호 오차가 작다는 이유로 양쪽 큰 오류가 없다고 판단하지 않습니다.

## 그림 2 · 공간을 얼마 더 써서 어떤 오차를 얻었나?
![실측과 이론 모델 비교 · FULL 직렬화 크기, 대표적 HLL 이론 RSE, 이번 20시행의 RMSE. RSE는 최대 오류 경계가 아닙니다.](/hll/plots/lab03-space-error.svg)
log2m 8 → 11 → 14에서는 레지스터가 256 → 2,048 → 16,384개로 늘어 저장 bytes도 커졌습니다. 실제 RMSE는 약 7.38% → 2.04% → 1.21%였습니다. 이론 곡선과 실제 RMSE가 정확히 겹치지 않는 것도 보여줍니다. 유한 표본·추정기의 편향·보정·입력 조건이 영향을 주므로 “이론값 이내만 나와야 한다”는 검증을 하지 않습니다.
비교는 regwidth=5·FULL 표현으로 통제한 결과입니다. 이 bytes를 실제 그룹 집계의 peak 메모리로 설명하지 않습니다.

## 별도의 hash seed 점검
벤치는 integer seed 0·4, text seed 0·5를 같은 50,000개 원본에서 비교합니다. 고유 해시 출력 문자열 수와 추정값을 함께 기록합니다. 특정 조합의 큰 과소 추정은 [해시 계약 심화](compatibility.md)에서 미확정 원인과 후속 조사로 설명합니다. 이 점검을 네임스페이스 오차 표본에 섞지 않습니다.
![별도 실측 · 해시 함수·seed 조합별 버킷 사용과 추정값. 주 정밀도 실험의 표본이 아니며 근본 원인은 아직 확정하지 않았습니다.](/hll/plots/lab03-hash-check.svg)
integer seed 4는 고유 해시 출력이 50,000개였지만 2,048개 중 1,024개 버킷만 사용했고 추정은 약 1,420으로 낮았습니다. 고유 해시 수만으로 비트 분포까지 검증한 것이 아니라는 사례입니다. text seed 5는 거의 모든 버킷이 채워져도 큰 과소 추정이 있어 버킷 사용 수 한 지표만으로 원인을 결론 내리지 않습니다.
이 결과를 숨기거나 이론 RSE 표본에 섞지 않습니다. 특정 조합의 관측이며 확장의 모든 입력에 대한 버그 판정이나 seed 추천으로 일반화하지 않습니다.
