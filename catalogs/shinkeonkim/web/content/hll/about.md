# hll은 어디에 쓰는가? · 고유 방문자 수를 작게 저장하기

## HLL은 “서로 다른 값이 대략 몇 개인가?”를 세는 도구입니다
HLL(HyperLogLog)은 고유 개수를 작은 저장 공간으로 추정하는 자료구조입니다. PostgreSQL의 hll 확장은 그 자료구조를 SQL에서 만들고 저장하고 합칠 수 있게 합니다. 방문 기록 자체를 압축해 보관하는 도구가 아니라, “서로 다른 사용자 ID가 몇 개인가?”라는 질문을 위한 요약입니다.
예를 들어 한 사람이 사이트에 20번 들어오면 방문 횟수는 20이지만 방문자는 1명입니다. HLL은 이 중 방문자 수를 추정하는 데 씁니다. 정확한 명단이 필요하면 원본과 COUNT(DISTINCT)를 사용합니다.

## 왜 쓰고, 어디에 쓰는가?
| 화면·업무 | 알고 싶은 것 | HLL을 검토하는 이유 |
| --- | --- | --- |
| 방문 분석 대시보드 | 오늘·이번 주·이번 달의 고유 방문자 | 일별 요약을 저장하고 필요한 기간끼리 합침 |
| 광고·캠페인 분석 | 여러 캠페인을 합쳐 접촉한 고유 사용자 | 겹친 사용자를 단순 합산하지 않고 규모를 추정 |
| 서비스·네트워크 통계 | 기간별 고유 기기·계정·IP의 수 | 원본 명단보다 작은 개수 추정용 요약을 보관 |

HLL을 선택하는 조건은 고유 값이 많고, 같은 분석을 반복하며, 작은 오차를 허용할 수 있다는 것입니다. 정확한 결제·정산·당첨 명단, 특정 사용자의 존재 확인에는 그대로 대체하지 않습니다. 계정·기기·IP 중 무엇을 같은 대상으로 셀지도 먼저 정해야 합니다.

## “요약한다”는 것은 무엇을 남긴다는 뜻인가?
요약 대상은 사용자 ID들의 집합입니다. 원본에는 누가 언제 무엇을 했는지가 있지만, HLL에는 고유 개수를 추정하는 데 필요한 해시 패턴의 통계가 남습니다. 많은 입력을 작은 레지스터 여러 개의 값으로 모으며, 각 레지스터는 담당 그룹에서 관측한 특정 패턴의 최댓값을 기억합니다. 실제 확장은 작은 입력에서 해시 목록을 보관하는 단계도 사용합니다.

| 자료 | 보관하는 것 | 할 수 있는 질문 |
| --- | --- | --- |
| 방문 원본 | 사용자 ID·방문 시각 등 각 기록 | 누가 언제 왔는가? |
| 일별 COUNT DISTINCT 숫자 | 예: 월요일 3명, 화요일 2명 | 각 날짜에 몇 명이 왔는가? |
| 일별 hll 스케치 | 고유 개수 추정용 해시 통계 | 날짜를 합쳤을 때 대략 몇 명인가? |

스케치는 이 요약 객체의 이름입니다. 최종 추정 숫자와 다릅니다. HLL에서 학생 이름이나 방문 시각을 되찾는 것은 목적이 아닙니다.

입력이 적을 때의 해시 목록과 입력이 커졌을 때의 그룹별 작은 통계는 저장 방식이 다릅니다. [HLL 안에 무엇이 저장되는가?](registers.md)에서 같은 ID 17·17·28·39가 어떤 값을 남기는지 실제 확장으로 따라갑니다.

## 숫자만 저장하는 것과 무엇이 다른가?
월요일 사용자 {1,2,3}, 화요일 사용자 {3,4}를 생각해 봅시다. 일별 숫자 3과 2를 더하면 5지만, 이틀 동안 온 서로 다른 사용자는 {1,2,3,4}의 4명입니다. 숫자 두 개만으로는 누가 겹쳤는지 알 수 없습니다.
HLL은 같은 규칙으로 만든 두 요약을 합쳐 이틀 고유 개수를 추정할 수 있습니다. 최종 숫자를 더하는 것이 아니라, 숫자를 읽기 전의 스케치를 합치는 것입니다. 실제 Lab에서도 일별 정확한 숫자의 합 70,000과 주간 정확값 25,000을 비교합니다. HLL의 주간 추정값에는 오차가 있으므로 [실측](results.md)에서 그대로 공개합니다.

## SQL 함수는 세 단계로 읽으면 됩니다
```sql
SELECT hll_cardinality(                 -- 3. 요약을 읽어 추정 숫자로 반환
         hll_add_agg(                  -- 2. 여러 입력 패턴을 하나의 hll 요약으로 집계
           hll_hash_integer(user_id)   -- 1. 정수 ID 하나를 해시 패턴으로 변환
         ))
FROM visits;
```
위 visits는 설명용 테이블 이름입니다. hll_hash_integer 하나가 방문자 수를 세는 것은 아닙니다. 문자열 ID라면 hll_hash_text를 쓰며, 그 뒤의 집계·추정 단계는 같습니다. [함수 역할과 예제](hashing.md)에서 입력 → 해시 → 스케치 → 숫자를 분리해 봅니다.

## 어떤 비용을 줄이고, 어떤 비용은 남는가?
작은 요약을 저장해 두면 기간별 고유 개수 질문을 할 때 큰 원본을 매번 읽는 작업을 줄일 수 있습니다. 처음 요약을 만들 때는 원본을 읽고 해시를 계산하며, 이후 변경을 반영하는 비용도 남습니다. HLL이 모든 COUNT DISTINCT보다 항상 빠른 것은 아닙니다. [초기 집계와 재사용 Lab](lab-performance.md)은 이 차이를 측정합니다.
