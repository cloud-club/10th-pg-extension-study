# Lab 02 · 일별 숫자와 주간 합집합

## 데이터와 정답
setup.sql은 7일마다 30,000개의 방문을 만듭니다. 일별 사람은 10,000명, 매일 ID 범위 시작이 2,500씩 이동합니다. 같은 날 사람마다 세 번 방문하고 날짜 사이 사람도 겹칩니다. 전체 방문 210,000행, 주간 고유 ID는 25,000개입니다.

```sql
SELECT day,count(*),count(DISTINCT user_id)
FROM hll_lab.events GROUP BY day ORDER BY day;
SELECT count(DISTINCT user_id) FROM hll_lab.events;
SELECT sum(hll_cardinality(sketch)),
       hll_cardinality(hll_union_agg(sketch))
FROM hll_lab.daily;
```
일별 정확값 합 70,000과 주간 정확값 25,000의 차이를 먼저 설명합니다. 추정된 일별 숫자의 합도 겹친 사람을 제거하지 않습니다.

## 그림 1 · 날짜 사이에 겹친 사용자는 어디에 있나?
![실측 원본 구성 · 날짜별 min/max 사용자 ID 범위. 각 날짜는 10,000개의 서로 다른 ID이며 날짜 사이 범위가 겹칩니다.](/hll/plots/lab02-overlap.svg)
가로 방향은 시각이 아니라 사용자 ID입니다. 둘째 날은 2,501–12,500이고 첫날은 1–10,000이어서 7,500개 ID가 겹칩니다. 각 날짜에서 10,000명을 세었다고 7일 동안 서로 다른 70,000명이 온 것은 아닙니다. 원본 SQL의 날짜별 범위·정확한 개수를 별도로 보관한 그림입니다.

## 그림 2 · 더하기와 병합의 실제 결과
![실측 · 일별 정확값 합·일별 추정값 합·주간 정확값·주간 스케치 병합. 점선은 주간 정답 25,000명입니다.](/hll/plots/lab02-union.svg)
앞의 두 막대는 일별 숫자를 더해 약 70,000으로 커졌습니다. 뒤의 정확한 주간 값은 25,000입니다. 스케치 병합은 날짜 사이 중복을 처리하는 합집합 요약을 만들지만, 그 결과를 읽은 숫자에는 추정 오차가 남습니다. 이번 병합은 약 23,268명으로 정답보다 약 6.93% 낮았습니다.
따라서 세 가지를 나눠 읽습니다. 단순 합산은 질문 자체가 다르고, 병합은 올바른 합집합 질문을 다루며, 추정 오차는 별도로 평가합니다. “병합이 가능하다”를 “언제나 정확하다”로 해석하지 않습니다.

## 무엇을 assert하는가?
bench.py는 원본 전체에서 만든 스케치와 일별 스케치를 병합한 결과의 동일성을 검사합니다. 이는 분할·병합의 일관성 확인입니다. 병합 추정값이 정답과 정확히 같다고 검사하지 않습니다. 실제 상대 오차는 별도로 계산하고 공개합니다.

## 바꿔 볼 조건
일별 ID 범위 이동을 0으로 하면 모든 날짜의 사람이 같고, 10,000으로 하면 날짜마다 겹치지 않습니다. 변경 후에는 정확한 주간 정답부터 다시 구합니다. 시간대·날짜 누락·그룹별 여러 행도 추가 수동 과제입니다. 설명의 25,000을 그대로 정답으로 유지하면 안 됩니다.
